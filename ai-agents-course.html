1 · The Agent Formula

Agent = Model + Instructions + Tools + Memory + Loop + Guardrails

A chatbot talks. An agent does things.

A plain chatbot takes your words and hands back words. An agent is what you get when you wrap that same brain in five more parts: directions, hands, a memory, a work loop, and brakes. The study sheet compresses the whole field into one line — Agent = Model + Instructions + Tools + Memory + Loop + Guardrails. Tap each part to see what it actually does.

Worked example: meet “Inbox Ivy”

Ivy is a small agent that keeps a busy shop owner's inbox at zero. Watch the formula show up in her build:

Model — a large language model reads each email and understands “this is a quote request, that one is spam.”
Instructions — “You are Ivy. Sort mail into Quotes, Bills, and Noise. Never delete anything. Sound like the owner.”
Tools — read_email, label_email, draft_reply, check_calendar. Without tools Ivy could only describe a tidy inbox.
Memory — remembers the owner's price list and that “Mike” is the good supplier, so drafts get smarter over time.
Loop — read a message → decide → act → check the result → next message, until the inbox is empty.
Guardrails — drafts need one-tap approval before sending; spending or deleting is never allowed.

Remove any one part and Ivy degrades: no tools → a commentator. No guardrails → a liability. No loop → a one-shot answerer. That is the formula doing real work.

2 · Agent vs Workflow + Function Calling

Who decides the next step — the code, or the model?

Two ways to build the same job

Workflow — follows fixed code paths. Step 1 always runs step 2. Like a recipe: reliable, predictable, and lost the moment reality goes off-script. Example: “If the email says ‘invoice’, forward it to accounting.”
Agent — the LLM chooses the steps and tools as it goes. Like a good hire with a goal: flexible, handles surprises, and needs guardrails because its path isn't fixed in advance.

Most real products are hybrids: workflows for the boring 90%, an agent for the messy 10%.

How function calling works

The model never touches your systems directly. It returns a tool name plus JSON arguments — a structured request. Your app runs the tool, then sends the result back, and the model answers using it. Four beats: ask → tool call → result → answer. Run it yourself:

3 · The ReAct Loop

Thought → Action → Observation, until the job is done

Reasoning + Acting = ReAct

Instead of answering in one shot, a ReAct agent works in a loop: it thinks out loud, takes one action (usually a tool call), observes the result, and thinks again — until the task is done. Step through a real task:

THOUGHTplan the next move
→
ACTIONcall a tool
→
OBSERVEread the result
↩

Task: “Find a plumber near Wilkes-Barre who can come Thursday and book the earliest slot.”

Now break it: the runaway loop

Loops can spin forever — re-searching, re-checking, re-spending. The sheet's four brakes: step limit, budget, timeouts, and detecting repeated actions. Set the brakes and run a badly-behaved agent that keeps “double-checking” forever:

4 · Memory

Short-term is the desk. Long-term is the filing cabinet.

Two kinds of memory

Short-term memory is the context of this task — the current conversation, the file you're working on, the last tool result. It's fast and free, and it evaporates when the task ends. Long-term memory is facts stored across sessions — saved to a database or file and loaded back next time: your name, your preferences, your standing instructions.

      5 · RAG — Answers With Receipts

      Retrieve first. Answer second. Guess never.

      Why models guess — and the fix

      A model answering from its training alone will happily invent your company's refund policy. RAG (Retrieval-Augmented Generation) fixes that: retrieve the relevant documents first, then let the model answer from them. The model becomes a good reader instead of a confident guesser.       6 · MCP, Evals & Safety

      One plug for every tool · proof it works · armor against tricks

      MCP — the universal plug

      Before MCP, every AI app needed a custom connector for every tool — a drawer full of one-off cables. MCP (Model Context Protocol) is an open standard to connect AI apps to tools and data via servers: build one MCP server for your calendar, database, or files, and any MCP-aware app can plug into it. USB-C, but for agents.

      Spot the injection

      Prompt injection is the agent-era con trick: hostile instructions hidden inside data the agent reads — a webpage, a review, a tool result.
