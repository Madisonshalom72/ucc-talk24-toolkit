Excel — Advanced

Excel is where most analysis starts: data lands messy, and your job is to clean it, calculate with it, and present it. Master the functions and the rest of this course gets easier.

1Functions do the heavy lifting

A formula starts with = and can point at other cells — change a number and every result updates. The five functions you'll use daily:

  • =SUM(G2:G17) — add a whole range. The colon means "everything between".
  • =AVERAGE(G2:G17) — the mean. =COUNT, =MAX, =MIN work the same way.
  • =E2*F2 — plain math between cells: quantity × price = revenue.
  • =IF(E2>=5,"Bulk","Standard") — a decision: test, value-if-true, value-if-false.
  • =VLOOKUP(K2,M2:N6,2) — find a value in a table and pull back a column next to it. The classic lookup.

2Cleaning data before you trust it

Real exports arrive with blank cells, text hiding in number columns ("8 (est)"), duplicates and stray spaces. Pros clean first: check totals against a hand count, sort to spot odd values, and never calculate on a column you haven't eyeballed. In the Final Project you'll rescue a sheet with exactly this kind of damage.

3From grid to dashboard

A dynamic dashboard is just formulas + charts wired together: summary cells (total, average, best region) feed titles and charts, so when next month's data pastes in, the whole dashboard refreshes itself. Power BI (Track 2) industrializes this idea — Excel is where you learn it by hand.

Power BI

Power BI turns tables into living dashboards: pick a category, pick a measure, and the visual does the math — for every row, instantly, and again every time the data refreshes.

1Visuals = category + measure

Every chart answers one question: a measure, broken down by a category. "Revenue by region", "Units by product", "Orders by month". Choose the pair and Power BI aggregates — sums, counts, averages — on the fly. A card visual shows a single headline number, like total revenue.

2DAX — formulas for dashboards

DAX is Excel's formula language grown up. A measure like Total Revenue = SUM(Orders[Revenue]) doesn't live in one cell — it's recalculated inside every visual, filtered by whatever the user clicks. Same idea as =SUM(...), but it follows the dashboard around.

3Model first, chart second

Pros organize tables into a star schema: one central fact table of events (orders — things you measure) surrounded by dimension tables that describe them (customers, products — things you slice by). Clean models make fast, correct dashboards; a single giant spreadsheet-table makes slow, confusing ones.

SQL

SQL is how you ask a database questions — and get exactly the rows you want back. Every query below runs for real, in your browser, against the BrightLine database.

1The shape of every query

SELECT  what columns you want
FROM    which table
WHERE   which rows qualify
GROUP BY  how to bucket them
ORDER BY  how to sort the answer

You describe what you want, not how to find it — the database engine does the hunting. WHERE revenue > 250 filters rows; aggregates like SUM(revenue) collapse many rows into one number.

2JOIN — questions that span tables

Databases split data into tables on purpose: orders knows the amount, customers knows who. A JOIN stitches them on the shared key: FROM orders JOIN customers ON orders.customer_id = customers.customer_id. After the join you can select columns from both tables as if they were one.

DATABASE · orders(order_id, date, customer_id, region, product, qty, price, revenue) · customers(customer_id, name, city, segment)

Python

Python is where analysis becomes automation: write it once, run it every week. With the pandas library, a table becomes a DataFrame you can filter, group and chart in single lines.

1Meet the DataFrame

df is your table in code. Columns are picked with brackets — df["revenue"] — filters are conditions — df[df["qty"] >= 5] — and pandas does in one line what takes Excel a column of formulas. Below, df already holds all 16 BrightLine orders.

import pandas as pd
df = pd.read_csv("orders.csv")   # 16 rows, columns: order_id … revenue

2groupby — the SQL idea, in code

df.groupby("region")["revenue"].sum() reads exactly like it sounds: bucket the rows by region, take the revenue column, add it up. It's the same move as SQL's GROUP BY and Power BI's category + measure — learn it once, recognize it everywhere.
